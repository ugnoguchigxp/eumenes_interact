# F09・F11 改修（2026-11-06）

この会話で提示した改修案と、利用者の「改善点を全部改善してください」に基づく。意味判断は既存のLLMループ、コードは観測・ID・出所・権限・実行状態を担う。

## 変更と完了条件

1. `page.find` / `page.list` に領域指定と観測に結び付く続きを設ける。候補は文書順、検索・ページ送り・広告・並べ替えを語句で分類しない。ARIA外の選択肢も固定の読取り専用検査から候補として閲覧する。
2. `site.search` はLLMが指定した欄だけに入力する。未指定では候補と保存済みの検索URLを返し、入力・遷移しない。部品の成功は入力の実行確認であり、検索結果の意味的成功ではない。
3. bot checkを語句で自動判定しない。LLMが観測に基づき待機・引継ぎを決める。待機中と申告したページでは入力を止める。実際のadapter拒否、承認・出所・回数制限は維持する。
4. `page.capture` はprepare/saveの二段階。prepareは対象の本文・構造・欠落を返し保存しない。LLMは依頼の必要要素と除外対象を照合し、範囲を選び直すか、確認参照と判断結果を指定してsaveする。ホストは参照をrun内の観測・tab・対象・範囲に結び付け、期限・再利用・変更を拒否する。撮影の前後で観測を照合し、変化した場合は保存しない。意味判断の正しさそのものをコードで保証したとは扱わない。
5. 部品契約・指示・scripted fixture・host適合検査を更新し、配布物をEumenesへ反映する。DB migration、新しい推論ループ、語句辞書、サイト専用分岐は追加しない。

## 実装結果

- 検索・ページ送り・並べ替え・広告・bot checkの語句辞書を削除した。候補は文書順で、所属領域・周辺本文・親IDを返す。`page.find` と `page.list` の `within` / `cursor` で、省略された候補にも到達できる。cursorは観測・問合せ・領域に結び付き、ページが変わると拒否する。
- `site.search` は `field` が未指定なら読取りだけを行う。保存済みの検索欄に一致した候補には `storedCandidate` を付けるが、自動選択しない。検索URLも提案だけを返す。入力の出所・権限の検査は維持した。
- ARIA外の選択肢は `page.find` の `inspect=true` で明示的に読む。読取りは固定関数で、領域と取得位置を指定できる。表示の有無も返す。実際のリンク先がある候補だけを開けるようにし、ハンドラーの属性から動作を推測してURLへ変換する自動経路を外した。遷移後に並べ替えの成否を推定する処理も外した。
- 確認待ちの判定はLLMが行い、`page.wait` の `condition=blocked` で入力を止める。観測に基づき `ready` とするまで入力を再開しない。読取りは継続でき、解けない確認画面は利用者へ引き継ぐ。
- 撮影は既定でprepareとなる。本文・必要な親子候補を返し、画像は作らない。saveには、同じrunの観測・tab・対象・範囲に結び付く5分間・単回使用の確認参照と、LLMの短い照合結果を要求する。撮影の前後にページが変われば保存しない。狭い子要素から親領域へ選び直すIDも返す。
- Eumenesはprepareに保存承認を求めず、saveだけに従来の承認を適用する。新しい読取りportも既存の観測・取消・所有者検査を通す。操作指示の旧revision 1は保持し、revision 2を追加した。
